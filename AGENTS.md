# ZynoSuite SDK

- Keep the runtime framework-neutral, ESM-only and limited to the explicitly allowlisted Suite HTTP operations. Suite owns the browser-facing contract; never import backend/TSF/shared runtime packages.
- `openapi.suite.json` is the versioned public contract snapshot. Regenerate it and `src/generated/` with `yarn openapi:generate <suite-openapi-file> --complete` after an approved server contract change. Do not hand-edit generated contracts.
- Preserve CRM-only authentication, indefinite null-expiry grants, atomic session-store coordination, matching-credential invalidation and the single active-or-pending logout state. Public requests must remain session-blind.
- Authored guides live in `docs/guide/`. `docs/api/` and `docs/.vitepress/dist/` are ignored build output, generated by `yarn docs:build` in CI and documentation deployment. Never commit generated documentation.
- Use Node 26 for repository tooling. Run `yarn check`, `yarn lint` and `yarn format:check` before review. A review alone must not rerun tests unless code was written first.
- Every commit includes `Co-authored-by: Codex <codex@openai.com>`.
- Package publication happens only from an approved release tag; do not merge, tag, publish or deploy without Sean's instruction.
